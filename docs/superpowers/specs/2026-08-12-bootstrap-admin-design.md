# 최초 관리자 부트스트랩 설계

날짜: 2026-08-12
상태: 승인됨

## 문제

시스템을 처음 설치했을 때 최고관리자 계정을 만들 방법이 필요하다.
지금은 `npm run db:seed`가 그 역할을 하는데, 두 가지가 걸린다.

- `.env`에 관리자 비밀번호를 평문으로 적어둬야 한다
- 설치하는 사람이 셸에 접근해 CLI를 돌릴 수 있어야 한다

웹 화면에서 처리하되, "사용자가 없으면 누구나 관리자가 될 수 있다"는 위험한 규칙이
필요 이상으로 오래 열려 있지 않게 한다.

## 위협

이 기능의 본질은 **인증 없이 최고 권한 계정을 만드는 경로**다. 다음을 막아야 한다.

| 위협 | 대응 |
|---|---|
| 교내망의 아무나 설치 직후 관리자를 선점 | 서버 콘솔에만 출력되는 256비트 토큰 요구 |
| 계정 오삭제·빈 백업 복원으로 문이 다시 열림 | 사용자 수 0명 **그리고** 토큰 보유 — 토큰은 서버 재시작 시에만 발급 |
| 동시 요청으로 관리자 2개 생성 | 토큰을 원자적으로 소진 — 승자는 반드시 하나 |
| 토큰 유출 후 재사용 | 계정 생성 성공 시 즉시 폐기, 재시작 시 새 토큰 |
| 토큰 비교 타이밍 공격 | `crypto.timingSafeEqual` |
| 게이트 실패 원인 노출 | "토큰 불일치"와 "이미 설정됨"을 구분해 알리지 않음 |

## 설계

### 토큰 수명

프로세스 메모리에만 둔다 (`globalThis` 보관 — Next의 번들 분리·핫리로드를 건너 공유하기 위해).
DB에 저장하지 않으므로 마이그레이션이 없고, 디스크에 남지 않고, 프로세스가 죽으면 함께 사라진다.
단일 컨테이너 배포라 다중 인스턴스 문제는 해당 없다.

부팅 시 `instrumentation.ts`가 사용자 수를 확인한다.

- 0명 → `randomBytes(32).toString("base64url")` 발급 후 콘솔에 접속 URL 출력
- 1명 이상 → 발급하지 않고 아무것도 출력하지 않음

### 이중 게이트

`/register?token=` 요청마다 **둘 다** 확인한다.

1. 토큰 일치 (timing-safe)
2. 사용자 수 0명 (매 요청 DB 재확인)

### 경쟁 조건

토큰 소진을 동기 블록 하나로 처리한다. Node는 단일 스레드라 이 블록이 쪼개지지 않으므로,
동시 요청 중 토큰을 가져가는 쪽은 반드시 하나뿐이다.

처리 순서는 **zod 검증 → 사용자 수 확인 → 토큰 소진 → 계정 생성**이다.
검증을 먼저 하므로 입력 오타로 토큰이 소모되지 않고, 계정 생성이 실패하면 토큰을 되돌린다.

### 생성되는 계정

`role: ADMIN`, `status: ACTIVE`, `emailVerified: true`,
**`mustChangePassword: false`** — 본인이 방금 정한 비밀번호이므로 강제 변경이 불필요하다
(시드 방식과 달라지는 지점).

`user`와 `account`(providerId `credential`, 해시된 비밀번호) 두 행을 한 트랜잭션에 넣고,
`recordAudit`에 `account:bootstrap`을 남긴다. 행위자는 방금 생성된 자기 자신이다.

생성 후 서버에서 바로 로그인시키고 대시보드로 보낸다. 실패하면 `/login`으로 보낸다.

### 권한 규약 예외

이 모듈은 `can()`을 호출하지 않는다. 로그인 개념이 없는 상태라 역할 기반 권한이 성립하지
않기 때문이다. 토큰 + 사용자 수 0명이 그 자리를 대신한다. **이 프로젝트에서 `can()` 없이
쓰기를 수행하는 유일한 경로이며, 다른 모듈이 이 예외를 따라해서는 안 된다.**

## 파일

```
src/instrumentation.ts              부팅 훅 — 토큰 발급 + 콘솔 출력
src/modules/bootstrap/
  bootstrap.token.ts                메모리 토큰 발급·검증·소진·복원
  bootstrap.schema.ts               zod
  bootstrap.repo.ts                 countUsers() · createAdminUser()
  bootstrap.service.ts              게이트 + 생성 + 감사로그
src/app/register/
  page.tsx                          게이트 통과 시 폼, 아니면 거부 화면
  bootstrap-form.tsx                폼 (클라이언트)
  actions.ts                        zod → 서비스 (얇게)
```

라우트는 `/register`를 쓴다. 시안의 초대코드 가입 화면이 나중에 같은 라우트로 들어오므로,
`page.tsx`에서 `token` 유무로 분기할 수 있게 둔다.

## 제거

`prisma/seed.ts`, `package.json`의 `db:seed`, `prisma.config.ts`의 `migrations.seed`,
`.env`/`.env.example`의 `SEED_SUPERADMIN_EMAIL`·`SEED_SUPERADMIN_PASSWORD`,
README·CLAUDE.md의 시드 관련 문단.

## 테스트

**토큰** — 발급 후 1회만 소진된다 / 틀린 토큰 거부 / 미발급 상태에서 거부 / 복원 동작 /
길이가 다른 입력에서 터지지 않음.

**서비스** — 사용자가 있으면 거부 / 없으면 생성 + 감사로그 / 계정 생성 실패 시 토큰 복원 /
잘못된 토큰이면 repo를 호출하지 않음.

## 검증 방법

기존 `admin@gbsw.hs.kr`를 지우고 서버를 재시작해 콘솔 URL로 계정을 만든 뒤,
같은 토큰으로 재접속하면 거부되는지 확인한다.
