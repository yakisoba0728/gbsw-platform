## 1. 어떻게 했나

**넓이는 스크립트로, 깊이는 브라우저로.** 두 층을 나눈 이유는 서버 액션을 curl로 못
몰기 때문이다 — 액션 ID가 암호화돼 있어 읽기와 권한 벽까지만 HTTP로 닿는다.

| 층 | 방법 | 규모 |
|---|---|---|
| 라우트 × 역할 | 로그인 쿠키 넷으로 전 라우트를 GET, 응답을 **그려짐/막힘/리디렉트**로 분류 | 47 라우트 × 4 역할 = **188 판정** |
| 조작 | Playwright로 서버 액션을 실제 경유 (Chrome, 헤드리스) | **약 96 검사** |
| 첨부 | 라우트 핸들러를 직접 두드림 (multipart) | 20 검사 |
| 서버 시작 | 빈 DB + 격리 워크트리 + 포트 3100 | 8 검사 |

기대표는 한 곳에서 베끼지 않고 **`can.ts`의 RULES · `nav.ts`의 roles · 게시판
`readRoles` 셋에서 따로 유도해 교차 대조**했다. 한 곳만 봤으면 그 한 곳의 실수를
그대로 통과시켰을 것이다.

## 2. 결과

- **라우트 × 역할 188/188 일치.** 막혀야 할 곳은 전부 막혔다.
- **남의 데이터 유출 0건.** 막힌 응답은 앱 셸뿐이고 본문이 없다 — 교사의 `/admin/logs`가
  444KB일 때 학생은 60KB에 감사 데이터 표식 0개다.
- 조작 검사에서 **기능이 안 되는 것은 나오지 않았다.** 아래 두 결함은 「되는데 화면이
  자리를 안 낸다」와 「막히는데 이유를 안 알려 준다」다.

## 3. 확정 결함 (2건, 모두 고침)

### 3.1 시작 전인 출입증을 아무도 취소할 수 없었다

서비스의 `CANCELLABLE`은 `REQUESTED · CONSENTED · APPROVED` 셋인데, 교사의 취소
버튼은 `pass/admin-view.tsx`의 **「지금 나가 있는 학생」 구역에만** 있었다. 그 목록은
`listActiveNow`가 채우므로 **지금 이 순간 나가 있는 학생만** 센다.

그래서 승인은 됐지만 아직 시작 전인 건은 갈 곳이 없었다 —
`/pass`의 두 구역 어디에도 안 뜨고(결재 대기 0 · 나가 있는 학생 0),
`/pass/history`에 취소가 없고, `/pass/<id>` 상세는 읽기 전용이었다.
학생의 철회(`withdrawable`)도 `REQUESTED · CONSENTED`뿐이라 그쪽으로도 못 갔다.

**증상:** 다음 주말 외박을 승인한 뒤 물러야 하면 그 주말이 올 때까지 방법이 없다.

**고침:** 출입증 상세에 취소 자리를 냈다. 조건은 `isRevocable()`이 소유한다 —
결재가 끝났고(`APPROVED`) 아직 안 끝난 건. 결재 대기 둘을 뺀 것은 그 자리를
승인·반려가 이미 답하고 있고 **반려는 사유가 필수라 기록이 더 낫기** 때문이다.
끝난 건을 뺀 것은 무를 것이 남아 있지 않아서다.

### 3.2 「권한 없음」과 「없는 게시판」이 일반 오류로 떨어졌다

**첫 보고는 이것을 실제보다 넓게 말했다.** 「권한 없는 페이지가 전부 일반 오류로
끝난다」고 적었는데, 브라우저로 확인해 보니 **`requirePermission()`이 막는 화면은
전부 이미 `/forbidden`으로 정확히 가고 있었다**(`/admin/logs`·`/admin/users`·
`/admin/settings`·`/merit/recent`·`/pass/history`·`/admin/community` 모두 403 화면).

응답 HTML만 보고 「셸 + 로딩 골격」을 오류로 읽은 것이 원인이다 — 리디렉트도 셸이
먼저 나간 뒤에 일어나면 같은 모양이 된다. **화면을 실제로 열어 보기 전에는 이 둘을
가를 수 없다.**

실제 결함은 좁았다. **`can()`으로 가를 수 없는 거부 둘**이다:

| 경로 | 그때 뜨던 것 |
|---|---|
| 학부모 → `/community/worry` (게시판별 읽기 권한) | 「화면을 열지 못했습니다」 |
| 학생 → `/community/notice/new` (게시판별 쓰기 권한) | 〃 |
| 학생 → `/pass/<남의 것>` (소유권 검사) | 「출입증을 불러오지 못했습니다」 |
| 누구나 → `/community/없는게시판` | 「화면을 열지 못했습니다」 |

앞의 셋은 게시판 행을 읽거나 소유권을 따져야 알 수 있어 **서비스가 조회를 마친 뒤에야**
`ForbiddenError`로 돌아온다. `requirePermission()`은 페이지 첫 줄에서 끝나므로 이 갈래를
못 잡는다. 넷째는 더 나쁘다 — **「없다」와 「못 본다」가 한 화면이 되어 구별되지 않았다.**

막히기는 정확히 막혔고 데이터도 새지 않았다. 잃은 것은 **원인을 알려 주는 일**뿐이다.

**고침:** 커뮤니티는 `orDenied()`가 갈라 준다 — `ForbiddenError`는 403,
`*_NOT_FOUND`는 404, 나머지는 그대로 올려 보낸다(`SLUG_TAKEN` 같은 것은 액션의 몫이다).
출입증 상세는 이미 있던 catch에 한 줄을 더했다. 둘 다 `forbidden()`이 아니라 redirect다 —
저장소가 `authInterrupts`를 켜지 않았고 `requirePermission()`도 같은 방식이다.

## 4. 고치지 않은 것

- **옛 주소가 meta refresh 1초 지연으로 넘어간다** — `/admin/students`·`/admin/invites`·
  `/merit/stats/{ranking,rules,teachers}`·`/merit/students/<id>`(+`/print`).
  셸이 먼저 나간 뒤 `redirect()`라 HTTP 307/308이 아니라
  `<meta http-equiv="refresh" content="1;…">`가 된다. `permanentRedirect` 쪽은
  `content="0"`이라 즉시 넘어간다. 북마크로 들어오면 1초 빈 화면을 본다.
  **`/forbidden`으로 보내는 길도 같은 성질이다** — 위 3.2의 고침도 1초를 쓴다.
  기존 `requirePermission()`이 이미 그렇게 동작하고 있었으므로 새로 생긴 문제는 아니다.
- **첨부 하나가 파일 없이 DB에만 남아 있다** — 공지사항 「adf」 글의
  `신생대_탐구보고서_1303_김동혁 (1).pdf`. 지난 세션의 `.uploads/` 정리 때 파일만 지워졌다.
  누르면 깨끗하게 404가 난다(예외 없음). **개발 DB만의 일이라 손대지 않았다.**
- **액션 시험이 없는 서버액션 4개** — `admin/community`·`community/[slug]`·`pass`·`scan`.
  이번에 브라우저로 실경로를 돌려 확인했으나 자동 테스트는 여전히 없다.
- **가입 시 `emailVerified: true` 하드코딩.** 실제 발송이 꺼져 있어 소유 증명 없이
  가입된다. CLAUDE.md에 적힌 의도된 상태다 — **이 검사가 그것을 「통과」로 덮지 않는다.**

## 6. 살아 있다고 확인한 방어선

의도대로 도는 것을 눈으로 본 것들이다. 결함이 아니라 **다음 감사가 다시 안 파도 되게**
적어 둔다.

- Better Auth의 CSRF Origin 검사 (`MISSING_OR_NULL_ORIGIN`)
- 겹치는 기간의 출입증 신청 → `OVERLAPPING_PASS`, 화면에 문구가 뜬다
- 외박만 보호자 확인을 거친다(`requiresConsent`), 외출은 바로 결재로 간다
- 위조 서명·지난 스텝 학생증 코드 → 판독 거부.
  **실효 창은 20초가 아니라 최대 40초다** — `verifyStudentCode`가 `step`과 `step-1`을
  함께 받는다(주석에 근거 있는 유예). CLAUDE.md의 「20초마다 갈린다」는 회전 주기다.
- 학생증 QR API는 **코드 문자열을 밖으로 안 내보낸다** (SVG path만)
- 첨부: 비로그인 401 · 쓰기 권한 없으면 **본문을 읽기 전에** 403(21MB 요청을 5초 안에 끊음) ·
  20MB 초과 413(서버 생존) · 확장자 위조 415 · 읽기 권한 없으면 못 받음 ·
  PDF에 `default-src 'none'; sandbox` + `nosniff` + inline · 한글은 내려받기 ·
  주소 뒤 파일 이름은 무시(첫 조각만 사용) · 대기 첨부 상한 ·
  첨부를 안 받는 게시판은 400
- **버려진 첨부 정리는 크론이 아니라 「그 사람이 다음에 올릴 때」 돈다**(`sweepMyOrphans`).
  올리다 만 파일은 그 사람이 돌아올 때까지 디스크에 남는다 — 의도된 설계다.
- 인증 발송 제한 **둘 다 실제로 걸렸다** — 대상별 5회/시간, IP별 20회/시간
- 초대코드: 재사용 불가 · 폐기하면 즉시 막힘 · **틀린 코드는 이유를 안 알려 준다**
- 비밀번호 초기화가 살아 있던 세션을 끊고, 임시 비밀번호는 변경 화면에 가두며,
  변경을 마치면 풀리고, 옛·임시 비밀번호는 죽는다
- 비활성 계정은 로그인이 막힌다
- 익명 게시판은 **교사에게도** 작성자를 안 보여 준다 (DOM에 이름·이메일 0건)
- 취소·반려·삭제·제거가 모두 사유를 요구하고 감사로그에 남는다
- 게시판 제거는 소프트 삭제이고 **되살릴 수 없다고 화면이 말한다**
- 명단: 학적이 재학이 아니면 학년·반·번호를 비운다
  (`grade: enrolled ? … : null` — 자리를 반납하는 것이 맞다)
- 부트스트랩: 빈 DB에 마이그레이션이 처음부터 다 붙고, 토큰 없이는 최초 계정 폼이 안 열리고,
  쓴 토큰은 즉시 죽고, 사용자가 생기면 `/register`가 초대코드 화면으로 돌아온다

## 7. 사고와 복구 — 검사가 실데이터를 건드렸다

시험 스크립트가 화면을 잘못 짚어 개발 DB의 실데이터를 세 번 바꿨다. **모두 되돌렸다.**

| 무엇 | 원인 | 복구 |
|---|---|---|
| 공지사항 게시판이 제거됨(`active=false`) | 행 탐색이 목록 전체를 감싼 컨테이너를 잡아 첫 행 링크를 땄다 | 되살림. 글 1건은 그대로였다 |
| `minjun@gbsw.hs.kr` 계정이 비활성화됨 | 계정 상세로 못 간 채 비활성 버튼을 눌렀다 | 화면으로 활성화 |
| 같은 계정의 명단 행이 비워짐(유예 + 학년·반·번호 소거) | 학적을 유예로 바꾸면 자리를 반납하는 **정상 동작**인데, 그걸 시험이 되돌리지 못했다 | 화면으로 재학·1학년 3반 7번 재입력 |

검사 뒤 모든 표가 시작 개수와 같다 — user 14 · Community 3 · StudentProfile 9 ·
MeritRule 114 · MeritAward 81 · Pass 2 · CommunityPost 4 · CommunityComment 9 ·
Invite 14 · VerificationCode 26. 벌점 기준 20/30 원복, 세 계정 로그인 정상.

### 감사로그는 지우지 않았다

`AuditLog`만 203 → 469로 늘었다. **그래서 `/admin/logs`에는 나중에 보면 놀랄 줄이 남아
있다** — 이정민·김민준 이름으로 된 `게시판 제거`(공지사항), 계정 비활성화·활성화,
학적 변경 3건, 벌점 기준 20/30 → 30/60 → 20/30, 그리고 수십 건의 글·댓글·출입증·부여.

**전부 이 검사가 남긴 것이다.** 지우는 편이 화면은 깨끗하지만, 감사로그를 지우기
시작하면 그 기록을 믿을 근거가 사라진다. 남기고 여기 적는 쪽을 택했다.

  옮길 수 있는지 확인이 먼저다.
