## 3. 테스트를 조이며 red로 드러난 것

이번 배치는 운영 결함과 테스트 결함을 섞어 다루므로 red도 둘로 갈랐다.

### 3.1 운영 결함을 재현해 바로 red였던 자리

- 배포의 base64 비밀번호 권고와 시연 계정이 만든 `createdById` 초대 정리는 새 테스트가
  기존 파일을 그대로 읽거나 호출했을 때 실패했다.
- 감사 기간 그룹·사유 라벨, 대시보드 상쇄점·외박 복귀 날짜는 실제 렌더 HTML에서 red였다.
- 출입증은 잘린 목록 수, 실패한 직접 부여 폼의 값 복구, 학생 신청 P2028 변환이 red였다.
- 커뮤니티는 고아/보상 삭제 감사와 커밋 뒤 디스크 오류 경로를 중심으로 첫 실행 3건이
  red였다.
- 명단 태스크는 NFD 머리글·신규 중복·현재 학년도 없음·saved/초대 수·액션 전달·성공
  문구를 여덟 수직 슬라이스로 나눴고 여덟 모두 red를 확인했다.
- 인증은 실제 목록 revalidate, prototype 키, 가입코드 오류 분류·입력 복원, raw 로그인,
  학부모 코드 목록·폐기 정책을 각각 red에서 고쳤다.
- 공용 UI에서는 `+82 010…`, GFM 체크리스트/언어 코드 class, `/merit/recent`의
  `aria-current` 두 개가 red였고, 상벌점 확인 버튼의 `type="submit"`도 렌더 결과로 잡혔다.

red를 없애려고 단언을 약하게 만든 곳은 없다. 화면 HTML, 함수 반환값, 서비스 오류 코드,
repo 호출 인자처럼 사용자가 승인한 관찰 경계에서 구현을 고쳤다.

### 3.2 기존 운영 코드는 맞아 결함 변이로 red를 확인한 자리

Phase A의 테스트 강화 20건은 테스트만 추가하면 현재 코드에서 green인 항목이 많았다.
이 경우 테스트가 생겼다는 사실만으로는 민감도를 증명하지 못하므로, 감사가 지목한 줄을
잠깐 지우거나 틀린 값으로 바꾸고 red를 본 뒤 운영 코드를 즉시 원복했다.

- 가입 실패 횟수의 한계 미만 조기 반환.
- 출입증의 보호자 대행 키 세 개 독립성, 충돌 창 ±60분, KST 종료일, QR 토큰 왕복.
- 커뮤니티의 기존+신규 첨부 산수와 `allowAttachments=false` detach 가드.
- 명단의 KST 생년월일, 반별 `classId`, 관리 대상/행위자 id, 초대 감사로그.
- 인증의 `{status:false}` 비밀번호 검증과 속도 제한 등 통합 불변식.
- 상벌점의 검색 OR/총건수 where, 학생 머리글 학년도, 세 통계 질의의 재적 또는 학생 id
  모집단, 일곱 집계의 학년도, 반 명단·요약의 트랙, 반 범위 결과. 실제 변이 실행에서
  recent 2건, 학생 머리글 1건, 집계 14건, 반 범위 1건이 각각 red가 됐다.

기준선의 단위 스위트는 141파일·2,281건이었고, 최종은 148파일·2,324건이다. 새 테스트
파일 7개와 강화된 기존 파일들이 43건을 더한다.

## 4. 고치지 않고 남긴 것

### 4.1 Phase A 49건

남은 항목은 없다. 열 커밋에 49개 ID가 한 번씩 들어갔다.

### 4.2 낮음 353건

되돌리기가 어려워진다.

### 4.3 지난 감사에서 이미 처분한 보류 5건

- **`auth-1-C03`** — 로그인 세션 발급 게이트가 이미 status·deletedAt을 보며,
  재적 기준을 택한 지난 결정 뒤에는 정리 메모로 남기기로 했다. 이번 감사에서는 중간으로
  다시 올라왔지만 같은 결정을 뒤집지 않았다.
- **`core-2-C01`** — Prisma P2010의 `meta=null`은 관측된 적이 없고 옵셔널 체이닝은
  TypeError를 false 판정으로 바꾸는 동작 변경이라 지난 처분을 유지했다.
- **`auth-1-R04`** — 로그인 껍데기의 금지 디자인 class는 사용자가 되돌린 시안이다.
  문서화된 예외로 둘지 토큰으로 복귀할지 사용자 결정 전에는 바꾸지 않는다.
- **`roster-2-R05`** — 두 통합 테스트의 같은 학년도 값은 `fileParallelism: false`라
  경합하지 않는다는 검증 라운드의 기각을 유지했다.
- **`shell-C03`** — 학년도 없음 상태가 도달 불가라는 옛 근거는 약해졌지만, 학생·학부모
  안내 링크를 다시 판단하는 일은 지난 결정을 재심하는 별도 작업이라 보류했다.

### 4.4 Phase B

단순화·보안·DB 구조 변경은 이 문서의 처리 범위가 아니다. Phase A가 만든 테스트 그물
위에서 `2026-09-01-implementation-plan.md` Phase B 순서로 진행한다. 특히 스키마 삭제는
데이터를 되돌릴 수 없으므로 Phase A에 섞지 않았다.

## 5. 이번 수정이 명시한 운영 제약

- Postgres 비밀번호는 지금도 Compose가 URL에 직접 끼운다. 새 설치는 hex 생성 명령을
  따라야 하며, 기존 값에 `/`가 있다면 URL-safe 값으로 교체해야 한다.
- 출입증 결재·활성 목록은 각각 상한이 남아 있다. 이번 배치는 상한을 없앤 것이 아니라
  잘렸다는 사실과 전체 수를 정확히 표시한다.
- 커뮤니티의 커밋 뒤 파일 정리 실패는 서버 로그에 남기되 이미 성공한 글 수정을 실패로
  뒤집지 않는다. 고아 청소 실패도 본 업로드를 막지 않는 기존 성질을 유지한다.
- 학생 한 명이 동시에 살려둘 수 있는 학부모 초대는 2장이다. 발급자가 교사여도 학생
  본인에게 귀속된 코드라면 목록에 보이고 학생이 폐기할 수 있다.
