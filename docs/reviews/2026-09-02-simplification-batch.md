## 2. 단계별 처리

### 2.1 죽은 코드 두 단계

- auth-client의 도달 불가 플러그인, 쓰지 않는 타입 별칭, 화면 상태 필드,
  `transitionUnexpired`의 무효 인자, datetime 함수와 상벌점·출입증의 도달 불가 분기를
  제거했다.
- 공용 UI는 실제 호출되는 모양만 남겼다. 아이콘 셋, Badge tone, `headerAlign`,
  Select 목록형 갈래, `/scan`의 죽은 제목을 걷고 관련 주석과 `CLAUDE.md`도 맞췄다.
- `--text-display`·`--color-green-press`는 코드와 디자인 스펙 표에서 함께 지워 재발
  경로를 닫았다.
- 화면이 쓰지 않는 `PostPage.total`은 제거했다. 첨부 응답 보안 헤더는 라우트의 죽은
  사본 대신 `next.config.ts` 한 곳이 소유하며, 테스트도 실제 소유자를 검사한다.

### 2.2 테스트 층

- `tests/helpers/session.ts`의 사용자 픽스처와 `tests/helpers/core-mocks.ts`의 감사·
  트랜잭션 목을 43개 테스트 파일이 공유한다.
- `withTransaction`은 자동 실행형과 테스트별 배선형을 모두 남겼고, `vi.mock(...)`은
  각 테스트 머리에 유지했다. repo 전용 tx와 명단 감사 묶음은 공용화하지 않았다.
- 존재하지 않는 파일을 가리키던 주석과 불필요한 목만 정리했다. 실제 재시도 분기를
  지키는 가입 repo 테스트와 확인되지 않은 중복 후보는 남겼다.

### 2.3 보안·감사로그

- 로그아웃 전에 사용자를 읽어 `auth:logout`을, 가입 직후 자동 로그인 성공에는
  `auth:login`을 남긴다.
- 학생 QR 발급은 프로필 조회 전에 `pass:request` 권한을 확인한다.
- 남의 미결 첨부와 소유자 없는 첨부에 대한 거부도 `authz:denied`로 기록한다.
- 전교생 정보가 브라우저로 나가는 명단 미리보기는 `roster:preview`를 남기되 이름·
  생년월일·학생코드는 metadata에 넣지 않는다.
- 전달 IP는 승인된 프록시 규약대로 `x-forwarded-for`의 마지막 홉을 신뢰한다.
- 학생이 발급하는 학부모 초대코드는 명단 발급과 같은 90일 만료를 쓴다.
- 최종 독립 검토에서 로그인·로그아웃 감사의 서비스 계층 우회를 발견해 바로잡았다.
  일반 로그인·가입 직후 자동 로그인·로그아웃은 `modules/auth`가 Better Auth 호출과 결과
  감사까지 한 동작으로 소유하고, 라우트·액션은 요청 경계만 맡는다.

### 2.4 DB 구조

변경 전에 로컬 개발 DB와 `gbsw_test`를 각각 덤프했다. 작업 당시 복구 파일은
`/tmp/gbsw-platform-stage5-backup.ByUnle/`에 만들었다.

- 사용하지 않는 인덱스 네 개를 별도 마이그레이션으로 제거했다.
- 글·댓글 삭제자/사유 네 열과 `Invite.usedAt`을 제거했다.
- `Invite.createdBy`는 `SetNull` 관계와 필수 `createdByName` 스냅샷으로 바꿨다.
- 독립 생명주기가 없던 `SchoolClass`를 없애고 `Enrollment.grade/classNo`로 인라인했다.
  기존 값을 먼저 백필한 뒤 nullable 학적과 새 유니크 제약을 적용했다.

기존 마이그레이션은 수정하지 않았다. 네 개의 새 migration SQL은 인덱스 제거, 열 제거,
초대 발급자 백필, 학급 인라인을 각각 독립적으로 담는다.

### 2.5 모듈 리팩터링

- 반별 통계는 별도 `classSummaries` 질의 대신 무범위 명단을 `foldClasses`로 접는다.
  평균 반올림과 전체 반 순위 조건을 테스트로 옮겼다.
- 규정별 `topRules`·`ruleStats`는 한 번의 `awardsByRule` 집계로 합쳤다.
- 통계의 부여 건수 모집단은 승인된 결정대로 현재 학년도 재학생으로 통일했고,
  통계 화면의 네 갈래는 캐스트 없이 이어지는 갈래표로 접었다.
- 출입증의 진행 중 상태는 공용 집합으로 모았지만 취소 정책의 `CANCELLABLE`은 별도
  개념이라 그대로 뒀다.
- 글 첨부 대조는 `attachToPost`의 갱신 수로 접었고, 명단 조회에서는 내보내기 전용
  전교 스캔을 `listForExport`로 분리했다. 2,000행 상한은 스키마 한 곳이 소유한다.

### 2.6 화면·공용 계층

- 사이드바와 모바일 서랍의 메뉴 나무를 `NavTree`로 합쳤다. 서로 다른 것은
  `density`와 `expand` 두 인자뿐이며, 경로 전이·최장 일치·역할별 노출을 실제 React
  상태 렌더 테스트로 고정했다.
- `/pass`와 `/merit`의 중복 오류 화면을 앱 오류 경계 하나로 합쳤다. 두 경로에서
  고의로 오류를 내 실제 브라우저로 사이드바·상단바가 남는 것을 확인한 뒤 임시 probe를
  모두 제거했다.
- 여섯 액션 파일의 오류 코드 변환과 세 파일의 `text`, 두 파일의 강한 `firstIssue`를
  `src/lib/action-message.ts`로 모았다. `MESSAGES`와 권한 문구는 각 액션 파일에 남겼다.
- `SkeletonTable`이 제목 폭·머리글 조작부와 실제 표에 가까운 기본 행 높이를 소유한다.
  로딩 알림은 시각 모양이 아니라 `loading.tsx`/Suspense fallback 경계가 한 번만 소유한다.
