## 요약

시안 준수는 **기계적으로 깨끗하다.** 금지 패턴 위반 0건 —
`text-pri` 0 · `font-bold`/`font-extrabold` 0 · 임의 글자크기 0 · 카드 그림자 0 · 그라디언트 0 ·
알약 버튼 0 · Tailwind 기본 팔레트 누수 0. 남은 그림자 3곳은 모달·말풍선·드롭다운으로 전부 정당하다.

**문제는 두 갈래다.**

1. **반응형이 사실상 없다.** 앱 전체 브레이크포인트가 31곳이고 대부분 앱 셸이다. 화면 파일
   40개에 반응형 유틸리티가 하나도 없다. 표 14개 중 **13개가 375px에서 잘린다** (측정된
   화면 기준). 1440px에서만 전 화면이 깨끗하다.
2. **같은 사실을 화면마다 다르게 그린다.** 발급된 코드 3벌 · 오류 표시 4벌 · 합계 칸 2벌 ·
   뒤로가기 링크 4벌 · 카드 안쪽 여백 6종. 시안 위반보다 이쪽이 사용자에게 더 크게 보인다.

## P1 — 폰에서 필수 흐름이 깨진다

### P1-1. `/admin/students`가 페이지 통째로 옆으로 밀린다 — 앱에서 유일

`main.scrollWidth 838 / clientWidth 365` (375px). 1024px에서도 남는다. 저장 버튼과 학년도
카드가 화면 밖이다.

**원인 (실측으로 증명됨, 추측 아님):** `admin/students/page.tsx:44`의 `<div className="grid gap-5">`.
암시적 열이 `auto`라 **max-content**로 커진다. 계산된 `grid-template-columns`가 실제로 822px
(컨테이너 333px)였고, `minmax(0,1fr)`로 바꾼 순간 `main.scrollWidth` 838→365로 떨어졌다.
밀어내는 max-content의 출처는 `student-table.tsx:215`의 `TableFrame minWidth={820}`.
같은 표를 쓰는 `/admin/users`가 멀쩡한 이유는 루트가 블록(`mx-auto max-w-6xl`)이기 때문이다.

**고침:** `grid gap-5` → `flex flex-col gap-5` (또는 `grid-cols-[minmax(0,1fr)]`).
**같은 패턴이 3곳 더 있다** — `students/loading.tsx:6` · `students/import/page.tsx:11` ·
`users/[userId]/page.tsx:82`. import 쪽은 업로드 후에만 표가 떠서 지금은 잠복 상태다. 넷 다 함께 고친다.

> 한 줄짜리 고침인데 앱에서 유일한 페이지 레벨 넘침이다. 가장 먼저 한다.

### P1-2. 학생이 자기 점수를 못 본다

학생·학부모 `/merit` 375px: `client 341 / scroll 560 / 숨김 219px`. "점수" 헤더가 "점"으로

`components/merit/award-history.tsx:46` `minWidth={canCancel ? 604 : 560}`.

### P1-3. 야간 부여 동선이 두 겹으로 막힌다

`/merit?grade=&classNo=` 375px: 숨김 217px. "벌점" 헤더가 "벌"로 잘리고, **상쇄·순점수 열과

## P2 — 태블릿과 일관성

### P2-1. 표 전략을 하나로 — `TableFrame`에 태운다

표가 14개다. 화면마다 다르게 대응하면 방언이 14개 생긴다.

375px 실제 예산은 **341px**(375 − `main p-4` 32 − 카드 테두리 2)이고 가장 좁은 표가 440px이다.
**즉 예외 없이 전부 잘린다.**

**폰 우선 표 5개 → 좁은 폭에서 카드 목록.** 열을 접지 않는다 — 접힌 열은 "값이 없다"로 읽힌다.
`class-roster`(548) · `award-history`(560/604) · `admin-view` 검색(460) ·
`merit/students` 검색(460) · `stats` WatchList(440).

**데스크톱 전용 9개 → 지금의 `overflow-x-auto` 유지.** 단 **스크롤 힌트를 넣는다** —
지금 `TableFrame`에는 그라데이션도 화살표도 안내 문구도 없어서(본문에 "옆으로"/"스크롤"
문자열 0건) 잘린 게 있다는 사실 자체가 안 보인다. `/admin/merit/rules`는 수정·삭제 버튼이
309px 뒤에 숨어 **화면상 버튼이 없어 보인다.**

**설계:** 지금 `children`이 불투명한 `<tbody>`라 `TableFrame`이 열을 숨길 수도 행을 카드로
바꿀 수도 없다. 판별 유니온으로 데이터 주도 모드를 하나 더 얹는다.

```ts
type Column<Row> = {
  key: string; header: ReactNode; cell: (row: Row) => ReactNode;
  width?: string; sort?: AriaAttributes["aria-sort"]; align?: "start" | "end";
  /** 375px에서 남는가. "primary"는 표당 하나 — 카드의 제목이 된다. */
  priority: "primary" | "secondary" | "desktop";
  cardSlot?: "title" | "trailing" | "meta" | "actions";
};
// narrow?: "scroll" | "cards"  — 기본 "scroll"(지금 동작 그대로)
```

`narrow="cards"`면 두 갈래를 함께 렌더한다 (`<ul className="lg:hidden">` +
`<div className="hidden lg:block">`). `display:none`이라 접근성 트리에는 한쪽만 남는다.
CSS로 `<td>`를 `display:block` 시키는 방식은 표 의미를 파괴하므로 쓰지 않는다.

기존 호출부 9곳은 시그니처 그대로 둔다. **옮기는 건 폰 우선 5개뿐이다.**

카드 한 장의 생김새는 이미 앱 안에 손으로 세 번 그려져 있다
(`parent-invite/page.tsx:64` · `users/[userId]/page.tsx:163` · `page.tsx:122`). 이 셋도 흡수된다.

### P2-2. 브레이크포인트가 아니라 컨테이너 쿼리다

같은 블록이 폭이 다른 두 자리에 동시에 선다 — `MeritTotalsCards`는 `/merit`의 전폭에도 서고
대시보드의 절반 폭 카드 안에도 선다. 뷰포트 폭으로는 옳게 굽을 수가 없다.

**이미 코드에 답이 있다:** `merit-totals.tsx:13`과 `print/page.tsx:113`이 `@container` +
`@md:grid-cols-4`를 쓴다. 새로 도입할 게 아니라 일반화하면 된다.

**규칙:** `lg:`는 앱 셸(사이드바↔하단탭)과 표↔카드 전환에만. 카드 안 재배치는 전부 `@container`.
지금 셸이 아닌 브레이크포인트 사용처 7곳 중 4곳(`page.tsx`·`invites/page.tsx`·
`parent-invite/page.tsx`·`users/[userId]/page.tsx`)은 전부 2단→1단이라 바꿔도 결과가 같다.

### P2-4. 초록 버튼이 한 화면에 여럿 (시안 위반)

`Button`은 variant를 안 주면 primary라 `bg-pri` grep으로는 안 잡힌다.

| 화면 | 개수 | 위치 |

남고 나머지가 자동으로 강등된다. 이 한 줄을 규격 문서에 넣어야 다음 모듈에서 또 어긋나지 않는다.

## P3 — 다듬기

### P3-1. `SectionCard`를 안 쓴 18자리

`rounded-card border border-line bg-surface` + `<h2 className="text-lg font-semibold">`가
`src/app/` 안에 그대로 반복된다. **이걸 정리하면 아래 셋이 곁다리로 함께 닫힌다:**

- **카드 안쪽 여백 6종** (`p-4`/`p-5`/`p-5 lg:p-6`/`p-6`/`p-6 lg:p-8`/`p-8`/`px-4 py-3.5`)
  → 규칙 3줄로: 표 카드 = `flush` + 셀 `px-5` · 폼/안내 카드 = `p-5` · 페이지 대표 카드 = `p-8`
- **제목 단계 눌림** — `headingLevel`이 대시보드 3곳에서만 쓰여, `/merit/students/[id]`는
  h1 → h2 → **h2 → h2**가 된다. `/merit/stats`는 페이지 h2가 아예 없이 h2가 5개다
- **카드 제목 크기 3종** — `text-lg`(기준) / `text-title`(페이지 제목이라 정당하나 규격에 없음) /
  **`text-sm`**(`page.tsx:298`, `import-form.tsx:261,496` — 본문과 같은 크기의 제목, 위반)

먼저 `SectionCard`에 `variant="panel"`(테두리 한 겹, 머리글 띠 없음)을 더해야
`users/[userId]`가 주석으로 문서화해 둔 두 규격을 잃지 않는다.

### P3-2. 표 본문 세로 패딩 3갈래

머리글은 `TableFrame`이 `py-2.5`로 고정하는데 본문만 `py-2`/`py-2.5`/`py-3`로 갈렸다.
가로 패딩을 `tableCellPadding()`으로 통일한 것과 같은 이유로 세로도 `TableFrame`이 정한다.

## 시안이 이 앱에 그대로는 안 맞는 지점

규격 문서가 이미 다섯을 번역했다(상태색 6쌍 · Pretendard · 제목 600 · 카드 여백 20px ·
mono 재배치). **아직 번역이 안 된 것 셋:**

1. **섹션 여백 64~96px** → 밀도가 정보다. 반 명단은 한 화면에 30명이 들어와야 한다.
   20/16px로 낮춘 건 옳다. 덜 된 건 "얼마나"가 아니라 **"어디에"** — 값 하나만 적고 카드의
   역할을 안 나눠서 코드에 6종이 생겼다. 여백은 취향이 아니라 카드의 역할에서 나와야 한다.
2. **"한 화면에 초록 버튼 하나"** → 마케팅 페이지엔 CTA가 하나지만 업무 화면엔 행동이 여럿이다.
   규칙을 버릴 게 아니라 판정 기준을 바꾼다 (P2-4).
3. **타이포 계단 64→48→36→28** → 이 앱은 22px이 천장이다. 계단져야 하는 건 글자 크기가
   아니라 **정보**다 — 375px에서 어느 열이 남고 어느 값이 둘째 줄로 내려가는가.
   그게 P2-1의 `priority`다.
